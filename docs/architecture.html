System Architecture

Factory Inventory Management System

A full-stack demo application for factory operations: inventory tracking, order management, demand forecasting, and spending analytics. Vue 3 frontend, Python FastAPI backend, and in-memory JSON mock data — no database.

Tech Stack

Frontend

Vue 3

localhost:3000
  • Composition API + Vite
  • vue-router (client-side routing)
  • axios (HTTP client)
  • Composables for shared filter state
Backend

FastAPI

localhost:8001
  • Python 3.11+, managed with uv
  • Pydantic models for validation
  • Auto docs at /docs
  • CORS enabled (dev: all origins)
Data

In-Memory Mock Data

server/data/*.json
  • No database — JSON loaded at startup
  • Inventory, orders, demand, backlog, spending
  • Filtered in Python on each request
  • Resets on server restart

Request / Data Flow

1
User adjusts a filter
Time Period, Warehouse, Category, or Order Status in FilterBar.vue updates shared refs in useFilters.js.
2
View calls the API client
A view (e.g. Dashboard.vue) calls api.getDashboardSummary(filters) in client/src/api.js, which builds query params and issues an axios GET.
3
FastAPI receives the request
Route in server/main.py accepts optional query params (warehouse, category, status, month).
4
In-memory filtering
apply_filters() and filter_by_month() narrow the in-memory Python lists loaded from JSON (no query language, no indexes — plain list comprehensions).
5
Pydantic validation & response
Results are shaped by response models (InventoryItem, Order, etc.) and returned as JSON.
6
Reactive UI update
Raw response is stored in a ref (e.g. allOrders); Vue computed properties derive filtered totals, charts, and tables that re-render automatically.

Key Patterns

Reactivity model: raw API responses are stored in refs (allOrders, inventoryItems); everything derived — totals, chart series, filtered tables — lives in computed properties, so the UI stays in sync automatically as filters change. Filtering itself happens twice: once server-side (query params narrow the JSON dataset before it's sent) and once client-side (computed properties derive views from what was returned).
